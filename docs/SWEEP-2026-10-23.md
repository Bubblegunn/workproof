## Findings

1. **bug** - `verify` (and so `verdict`) fails on a report the tool just wrote. Repos: tj/commander.js ba6d13d, torvalds/uemacs 325a8e9, sinatra/sinatra cb22afd, psf/requests 611c616, django/django 512b92a. Command: `workproof --repo R --author <top email> --out r` then `workproof verify r.json --repo R --fingerprint-key K`. Expected: all figures reproduce. Actual: exit 1, 7 figures differ (commitShare, cadence, footprint, commitSize, absenceFactor, survivingLines, survivalByCohort); commander: 501 commits in the report, 506 on verify. `verdict` on sinatra says "Do not trust as is". It happened in 5 of the 13 repos, each with another address under the same author name (1, 2, 2, 3, 1 other addresses). Cause (read, not tested): the explicit `--author <email>` is exact (analyse.ts), but the report hides emails and stores only names, and `verify.ts:66` resolves the identity by name, which also takes in the other addresses. The comment at `verify.ts:61` assumes a merged identity, which holds only for the config-derived path. Not tested: `--emails` runs.
2. **bug (cause unknown)** - psf/requests 611c616: `figures --repo R --author me@kennethreitz.com --json` gives "all authors, non-merge commits" 4882; plain git gives 4883 (`git log HEAD --no-merges`, author date, no window). Same difference with `--author "<name>"` and in the report (`commitShare.total` 2823 vs 2824). Cause not investigated.
3. **bug (cause unknown)** - expressjs/express 0dee2c5: `whitespace-only commits` is 31 for tj@vision-media.ca; reference (raw added+deleted > 0 and `-w` totals both 0) gives 32. Cause not investigated; src/figures.ts around the `wsOnly` filter compares files by path between the raw and `-w` runs, which can differ for renames (unchecked).
4. **unresolved** - psf/requests: surviving-line check with `--no-exclusions --sample 1` gives linesAttributed 28186 and my `git blame -w -M` reference 28225 (diff 39). Also file counts differ by 2 to 6 in click (170 vs 176), sinatra (288 vs 290), express (211 vs 214), requests (123 vs 125). For the file counts, the cause is most likely empty text files, which the tool lists and `git grep` does not; the script now adds empty files and symlinks (commander's 3 symlinks explained its first 3-file difference) but the sweep was not re-run, so this is unconfirmed. The 39-line difference on requests is unexplained.
5. **slow** - django/django 512b92a (35,049 commits, 279 MB): default report 71 s, verify 98 s, verdict 85 s, mine 74 s, windowed report 78 s, report without --author 35 s, mine without --author 68 s. Figures took under 30 s. All other repos done were under 30 s per command (flask figures about 6 s on 132 commits). Cause not investigated.

## Findings (second run)

Format: repository + sha, command, expected, actual, severity, probable cause (read from src/, not tested).

1. **medium, wrong output** - any repo (probe repo, machine time zone UTC+3). `workproof --repo R --author A --since "05/01/2024" --out x`; also `--since "2024-1-5"`, `--since " 2024-01-01"` (leading or trailing space) and `--since 2020-02-30`. Expected: error or the date as written. Actual: exit 0, tenure window silently becomes 2024-04-30, 2024-01-04, 2023-12-31 and 2020-03-01 (a day early for the first three, rolled over for the last). Other strings (`2 years ago`, `yesterday`, `20240105`, `2020-13-45`, `0000-00-00`) exit 1 with only "Invalid time value". The same strings in `reviews` fail with "git could not read the date ..." and in `figures` print a "not computed" row with exit 0: three behaviours for one option. Cause: `tenure()` in src/figures/commits.ts:9-10 does `new Date(override.since)` with no validation; analyse.ts:218-219 builds more dates from the result.
2. **medium, slow** - babel/babel 0b1ff08 (18,707 commits): default `report --author sebmck@gmail.com` 179 s, `verify` 184 s, `verdict` 73 s, `mine` 75 s, windowed report 74 s; vim/vim f9b3d0d (24,687): `figures` 71 s (by name 73 s), `verdict` 62 s, `mine` 67 s; imgui 4e99c0a: `figures` 31 s (by name 40 s); pandoc a3dce9e, curl dc8bf85, django 512b92a: report/verify/mine 30 to 58 s; vuejs/core 0ff253b: verdict 41 s. Expected: under 30 s. Cause (not measured): `survivingLines` starts one `git blame -w -M` per text file (src/figures/surviving.ts:92-100), so cost follows the number and size of files at HEAD, not the commit count (babel is slower than django); `figures` runs the raw and the whitespace-ignoring numstat over all of the author's commits (figures.ts:360-362), which is expensive for authors with 7,000 to 16,000 commits. Load average 85 inflates all of these.
3. **medium, incomplete output** - `owner --path <file> --claim <name>` on a single large file: actions/checkout f548e57 `dist/index.js` (42,269 lines), ant-design 599b78b `components/locale/__tests__/__snapshots__/index.test.tsx.snap` (384,089), numpy c33148c `numpy/linalg/lapack_lite/f2c_d_lapack.c` (41,864), imgui 4e99c0a `imgui.cpp` (18,777). Expected: the whitespace-and-moves row computed. Actual: exit 0, row "not computed (timed out after 20 s)", the claim row says "surviving lines not computed ... plain blame 1.0%". Plain blame completes. The header note says "120 s for each blame pass", but the 20 s per-git-call limit decides for a one-file call (a manual `git blame -w -C` of dist/index.js takes 23 s). Cause: owner.ts `GIT_TIMEOUT_MS` (20 s) applies to each blame call; the note (owner.ts:312) lists both limits without saying which one binds. `owner` also took 54 to 68 s wall on curl, ant-design, numpy, imgui, vim (two blame passes plus history).
4. **medium, silent no output** - `figures --brief --repo R`. Expected: the brief, or a message that it was skipped. Actual: exit 0 and empty output on 22 of 38 repos. 8 are over `BRIEF_MAX_COMMITS` = 20,000 (figures.ts:650): ansible, ant-design, curl, dependabot-core, django, laravel, numpy, vim. The other 14 (lodash 7,710; vuejs/core 7,234; tmux 12,589; express 6,182; moment 4,132; vue 3,593; reveal.js 3,368; shadcn 2,592; babel, pandoc, monero, prettier, rubocop, imgui) ran into the default 3 s budget (3.04 to 3.08 s). Not stable: express 0dee2c5 printed 21 lines in 1.1 s early in the run and in 11 of 20 repeated runs under load, nothing in the other 9 (2.4 to 3.1 s). Cause: `runBrief` (figures.ts:760-770) prints nothing on timeout by design, and the brief reads the whole numstat history (`git log --numstat` of express: 0.7 s CPU, 2.3 s wall at load 85). The usage text does not mention either limit. Same silent exit 0 for a non-repository, an unborn HEAD and a bare repository.
5. **low, confusing error** - empty repository / unborn HEAD (`git init`; or `git checkout --orphan` in a repo with history). `report`, `mine`, `verify` exit 1 with a message that begins with the whole internal command line (`Command failed: git -c diff.renames=true -c diff.algorithm=myers ... log --numstat --format=... -M`) and ends, after about 300 characters, with "fatal: your current branch 'master' does not have any commits yet". `reviews` exits 2 "not computed (fatal: ambiguous argument 'HEAD' ...)", `owner` exits 1 "fatal: Not a valid object name HEAD", `figures` exits 0 with "not computed" rows, `figures --brief` is silent.
