## How far the numbers can be trusted

**Line counts are weak evidence, so please don't present them as productivity.**
- The 30,002-line dataset and the 1,800-line lockfile make up nearly all of the raw additions. They are data and generated output, not authored code. I have left them out of the totals.
- In the files I sampled (export, options, cache, JSON export tests, CLI flag, sorting tests), most lines are short, near-identical functions or one-line asserts that differ only by a number. I looked at the first lines of each file, not every line. Line counts for these files overstate the amount of distinct logic. I did not assess correctness.
- The sorting-test commit has a net change of −64 lines. It removes a 119-line file of structured tests, which I saw only in the diff, and replaces it with 55 one-line asserts. A reviewer reading the history could read that as reduced test coverage, not added coverage. Priya should check this commit before citing it.
- Deletions and the reverted cache work are not counted as output.

- The CLI flag commit was authored 28 Jun but committed 3 Jul. It is inside the window by author date and outside it by commit date. A "later note" docs commit on 14 Jul is excluded.
