## 4. How far the numbers can be trusted

**Reliable**
- Authorship and dates for commits under `priya.raman@acme-corp.example` are reliable. Blame at HEAD confirms those lines still exist and are attributed to Priya.
- Line counts for the items in section 2 are exact, from `git log --numstat`.

**Needs confirming or caution**
1. **Two identities.** Three commits use `priya <priya@priya-laptop.invalid>`. I have assumed it is Priya's laptop config. That adds +5 lines (the 20 Jan fix) to the period. One is in the period and two (Dec 2025) are not. Please confirm it is yours.
2. **Boundary commit.** "CLI flag for JSON export" has author date 28 June but was committed on 3 July. It is in the period by author date and outside it by commit date. I counted it separately (297 vs 342) rather than choose.
3. **The sorting rewrite removed more than it added.** The 2 June commit replaced 119 lines of existing tests with 55. The new tests are one-line checks that call a function with an empty list, so they would not catch real sorting bugs. As evidence it is weak. A reviewer who opens that commit could read it as reducing coverage. I would not cite it as test coverage for Lena's stable sorting.
4. **Much of the code is repetitive.** The export-option, JSON export and test files are made of near-identical short functions, not varied logic. Line counts overstate effort and complexity here. The same applies to the 90-line JSON export test file and the 40-line pagination doc, which consist of numbered repeated lines.
5. **Lines are a weak measure.** There are no review comments, PR discussions, issue links, test results or usage numbers in this history. Only one change (PR #41) went through a pull request.
6. **Shared history.** The repo also contains years of commits by many other contributors. Only the commits listed here are claimed.

## 5. What this history cannot show

For a senior promotion, the committee will probably also want:
- Why the pagination cache was reverted, and what was learned.
- Design or technical decisions behind export options and JSON export.
- Reviews given (Tomasz Varga's note is the only mention).
- Adoption or user feedback for the new features.
- Mentoring, incident response or cross-team work.

Written statements from Tomasz Varga and Lena Fischer, or links to the PR #41 discussion, would support those points better than line counts.
