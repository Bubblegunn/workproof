## Problems with the code as evidence

The source and test files I opened are made up of one-line, near-identical functions. Examples:

- `jsonexport.py`: `def export_row_1(row): return {"k1": row}`, and so on.
- `test_jsonexport.py` and `test_sorting.py`: `def test_export_N(): assert export_row_N(1)`, and so on.
- `cli_export.py`: `def cli_export_N(argv): return argv[N:]`, and so on.
- `exportopts.py` (PR #41, the "export options" feature): 47 functions of the form `def opt_N(table, flag=N): return table`. They do nothing.

Test and function counts built from these files would be inflated by repetition. For example, `test_jsonexport.py` has 90 test functions on 90 lines. I wouldn't describe any of this as a substantial feature, or cite test counts, unless the real implementation exists elsewhere and the committee gets a different account of it. If a reviewer reads the code, these files will not support a claim of complex work.
