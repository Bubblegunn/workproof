## How far the numbers can be trusted

**Problems you should know about before submitting:**

1. **Test coverage went down.** 16de668 (2 Jun, "test: cover stable sorting") is a net **−64 lines** (+55/−119). It replaced a real test suite for sorting with 55 one-line stubs, each asserting `stable_sort_N([])`. Those functions aren't defined anywhere I could find. The old tests exercised sort-by-column, reverse sort and custom sort keys. Don't cite this commit as test work. A reviewer who opens it will see a regression. You should restore the tests or be ready to explain it.
2. **Line counts are a weak measure here.** The new files are highly templated. For example, `cli_export.py` is 20 near-identical one-line functions, `exportopts.py` is 12, and `test_jsonexport.py` is 90 stubs asserting `export_row_N(1)`. I counted the lines but would not call them 157 lines of meaningful logic. I would not lead with line counts. If the real code is more substantial than the history suggests, describe it by behaviour.
3. **Two author identities.** Commits under `Priya Raman <priya.raman@acme-corp.example>` are clearly yours. Others use `priya <priya@priya-laptop.invalid>`, a local laptop config. That covers the Jan 20 fix, plus the units helpers I excluded. I attributed the fix to you on the assumption it's your laptop. Please confirm, since git can't.
4. **Dates are as recorded, not independently verified.** Git author dates can be set freely. The two with a gap between author and commit date are noted above.
5. **No impact data.** Nothing here shows usage, adoption, performance, bugs prevented or time saved. The repo can't answer "how much did it matter".
